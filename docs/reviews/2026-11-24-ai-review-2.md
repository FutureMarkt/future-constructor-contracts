### AR2-01. Renounce на вестинге

`AdvancedVestingWallet` — `VestingWalletCliff` + `Ownable2Step`. Двухшаговым сделали только `transferOwnership` (AR1-04). `renounceOwnership` остался одношаговым из OZ `Ownable`: пишет `owner = 0` и стирает `pendingOwner`.

`VestingWallet.release(token)` делает `SafeERC20.safeTransfer(..., owner(), amount)`. OZ ERC-20 в `_transfer` ревертит `ERC20InvalidReceiver` на нулевой получатель, в том числе при `amount == 0`. После renounce ни до cliff, ни после него токены не вывести. ETH `Address.sendValue(payable(address(0)), amount)` сжигается.

Это не кража третьим лицом: вызов делает текущий владелец. Это необратимая потеря вклада (ошибка, скомпрометированный ключ, «отказ от владения» по привычке Ownable). На токене с паузой такой путь уже закрыли (AR1-01). На вестинге — нет.

PoC: `AR2-01` в `test/AiReview2.poc.ts`.

### AR2-02. `startTimestamp == 0` после AR1-08

AR1-08 закрыл график с `end <= now`: `start=0, duration=1000` теперь `VestingAlreadyFinished`. Проверка:

```solidity
if (uint256(startTimestamp) + uint256(durationSeconds) <= block.timestamp)
```

`start=0` и `duration = now + 1 год` сумму не проваливают. OZ считает линейно от нуля: к 2026 году vested ≈ `now / (now + 1 год)` ≈ 98%. Cliff при `start=0` тоже в 1970-м.

Это ловушка UI, который подставит нули «на потом заполним start», а duration возьмёт из поля «срок». Вклад почти сразу у бенефициара, вестинг не работает. Не кража: создатель сам задаёт параметры.

PoC: `AR2-02`.

### AR2-03. Налог на LP

`_quoteTax`: вход в помеченный пул — sell, выход — buy. `addLiquidity` не-владельца идёт `transferFrom(user, pair, amount)` → sell, пара получает `amount - fee`, mint LP считает фактический баланс (перекос резервов). Вывод LP — `pair.transfer(user)` → buy.

Владелец и фабрика исключены, поэтому сид ликвидности владельцем без налога, как задумано. Сторонний LP платит с обеих сторон. Чёрного списка нет, перевод не ревертит из-за налога.

PoC: `AR2-03`, `AR2-03b`.

### AR2-04. Непомеченная пара

Модель требует, чтобы владелец вызвал `setPool` после появления пары. Пока адрес не в `_pools`, перевод на него — кошелёк–кошелёк. Вторая пара (V2, V3, другой DEX) — рынок без налога. Владелец может забыть пометить или пометить только «официальную» пару.

Это не обход со стороны кода налога, это граница модели. Посторонний не выключает налог на уже помеченной паре.

PoC: `AR2-04`.

### AR2-05. Секвенсор без stale-проверок

AR1-02 добавил фид секвенсора. Реализовано по примеру Chainlink: `answer != 0` → down, `startedAt == 0` или в будущем → невалидный раунд, grace `<= 1 hours`. Нулевой адрес отключает проверку (L1). Нулевая USD-комиссия фид не читает — так и задокументировано.

Ценовой фид параллельно проверяет `answeredInRound`, `updatedAt` и возраст. Секвенсор эти поля игнорирует (`unused-return` у Slither). Просроченный «up» пропускает квоту. Потолок ущерба — комиссия деплоя, не балансы токенов.

PoC: `AR2-05`.

### AR2-06..08 (Info)

Стандартный V2-роутер на sell падает на `K`, если считает полный `amountIn`. Мок в репозитории подставляет фактический вход. Токен при этом отдаёт `value - fee` и не ревертит — honeypot нет. Интегратору нужен supporting-fee маршрут. Review №1 это уже отметил как не-дефект; здесь фиксируется расхождение мока с байткодом роутера.

На фабрике нет rescue для ERC-20. Штатный путь туда токены не кладёт.

Renounce деплоера до `setFactory` — операционная ошибка при раскатке, не атака из мемпула.

## Что проверено и находкой не стало

- Buy + sell ≤ 1000 bps — константа, сеттера потолка нет. После деплоя ставка только вниз, по каждой стороне отдельно.
- Владелец, immutable `factory` и `setExcluded` без налога. Выключить автоматическое исключение через mapping нельзя. После `acceptOwnership` исключён новый владелец.
- Mint/burn без налога (AR1-03). Cap 0 = выкл. `mint` не пробивает cap. `burn` / `burnFrom` по allowance, флаг `hasBurn`.
- Продажа из-за налога не ревертит: fee ≤ 10%, `value - fee` не андерфлоуит. Чёрного списка нет. Honeypot в токене нет (AR2-06 — про роутер, не про `_update`).
- Ownable2Step на токене, фабрике, деплоерах, вестинге. Renounce на паузе токена и фабрики запрещён.
- Фабрика масштабирует whole-token `initialSupply`, раздачу и cap один раз. Токен сырые единицы второй раз не умножает. Переполнение — `SupplyOverflow` / `CapExceeded`.
- Комиссия в нативе, Chainlink, границы цены, `FeeRoundsToZero`, `maxFee`, сдача, fallback на fee recipient, оба отказа откатывают tx.
- Permit: EIP-712 имя ≤ 31 байт, версия `"1"`, `PERMIT_TYPEHASH`, просроченный дедлайн и чужая подпись ревертят. Votes двигают units на каждой ноге, включая налог. Потолок `uint208`. Часы — номер блока (дефолт OZ).
- Permit и `delegateBySig` делят `Nonces` — поведение OZ, не дефект обёртки.
- `setFactory` один раз, `onlyOwner`. CREATE2-соль чужой `msg.sender` не повторит.
- Инвариант `totalSupply` после облагаемого перевода: сумма ног равна `value`. Проверено циклом в PoC.

Владелец токена по-прежнему может pause (если купили), mint без cap, пометить любой адрес пулом, исключить адрес, сменить fee recipient, продать без налога. Это продукт, не находка, пока власть не становится необратимой помимо записанных правил.

- Это не аудит.
